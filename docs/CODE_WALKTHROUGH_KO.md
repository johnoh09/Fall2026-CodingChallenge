# 코드 이해하기

## 1. 수업 예제에서 무엇이 늘어났나?

사진의 기본 코드는 `web/src/App.tsx`에서 서버의 `/api/hello`로 요청을 보내고,
`server/index.js`가 `{message: 'hi'}` 같은 JSON을 보내는 구조입니다.
Frameboard도 같은 방식입니다. 다만 요청 종류가 컬렉션 생성, 사진 저장,
로그인 등으로 늘어났고 데이터가 SQLite에 남습니다.

## 2. 프론트엔드와 백엔드

| 부분         | 역할                                | 파일                              |
| ------------ | ----------------------------------- | --------------------------------- |
| React 화면   | 버튼, 사진 목록, 입력창을 보여줌    | `web/src/App.tsx`                 |
| 재사용 화면  | 사진 카드, 컬렉션 카드, 팝업        | `web/src/components/`             |
| HTTP 함수    | `fetch` 요청과 오류 처리를 모음     | `web/src/api.ts`                  |
| Express 서버 | URL별 요청을 받아 처리함            | `server/app.js`, `server/routes/` |
| SQLite       | 사용자, 컬렉션, 사진, 권한을 저장함 | `server/db.js`                    |

`server/index.js`는 서버를 켜는 역할만 맡습니다. 요청 처리 코드를 별도
파일에 나눠 두면 새로운 기능을 추가하거나 오류를 찾기 쉽습니다.

## 3. 사진을 Save하면 어떤 일이 생기나?

1. React에서 Save 버튼을 누르면 SaveDialog가 열립니다.
2. 사용자가 저장할 컬렉션을 고릅니다.
3. `POST /api/boards/컬렉션ID/pins`에 `{imageId: 'sample-29'}`를 보냅니다.
4. 서버는 쿠키로 사용자를 확인하고 컬렉션 편집 권한이 있는지 검사합니다.
5. 서버가 아는 이미지인지 확인하고 SQLite의 pins 테이블에 넣습니다.
6. 결과를 받은 화면이 컬렉션을 다시 읽고 저장 완료 메시지를 보여줍니다.

DB의 `UNIQUE(board_id, image_id)`가 같은 컬렉션에 같은 사진이 두 번
저장되는 것을 막습니다. 화면 버튼만 막는 것보다 서버/DB에서 보장하는
것이 중요합니다. 브라우저 외부에서도 API에 요청할 수 있기 때문입니다.

## 4. SQLite는 왜 쓰나?

JavaScript 배열에만 저장하면 서버를 끌 때 내용이 사라집니다.
SQLite는 실제 파일에 데이터를 저장하므로 다시 켜도 컬렉션이 남습니다.
별도 DB 계정이 필요 없고 Node.js의 `node:sqlite`를 사용합니다.

SQL의 `?`에는 사용자 입력을 따로 전달합니다. 입력을 SQL 문자열에 직접
이어 붙이지 않아 SQL injection을 예방합니다. 관련된 변경은 transaction으로
묶어 전부 성공하거나 전부 취소되게 합니다.

## 5. 로그인은 어떻게 구분하나?

처음 접속하면 서버가 게스트 사용자와 임의의 세션 토큰을 만듭니다.
토큰은 HttpOnly 쿠키에 들어갑니다. 이후 요청에 쿠키가 자동으로 붙으면
서버가 어떤 사용자인지 확인할 수 있습니다.

가입하면 현재 게스트 사용자가 계정으로 바뀌어 컬렉션도 유지됩니다.
비밀번호 원문은 DB에 넣지 않고 랜덤 salt와 scrypt로 계산한 값을 넣습니다.
로그인할 때는 입력한 비밀번호를 같은 방식으로 계산해 비교합니다.

## 6. 공유 권한은 어떻게 나누나?

| 사용자                   | 볼 수 있음 | 사진 추가/수정/삭제 | 공유 설정/컬렉션 삭제 |
| ------------------------ | ---------- | ------------------- | --------------------- |
| 소유자(owner)            | 가능       | 가능                | 가능                  |
| 계정 초대자(editor)      | 가능       | 가능                | 불가                  |
| 편집 링크 방문자(editor) | 가능       | 가능                | 불가                  |
| 보기 링크 방문자(viewer) | 가능       | 불가                | 불가                  |
| 아무 권한도 없는 사람    | 불가       | 불가                | 불가                  |

공유 링크에는 추측하기 어려운 임의 토큰을 넣습니다. Link off로 바꾸면
기존 토큰이 사라집니다. 권한 설정을 바꿀 때도 토큰을 교체합니다.
버튼을 숨기는 것뿐 아니라 서버가 모든 변경 요청의 권한을 검사합니다.

## 7. 공동 편집 중 충돌은?

사진에는 `version` 번호가 있습니다. 두 사람이 버전 1을 보고 있는데
한 사람이 먼저 수정하면 버전 2가 됩니다. 나중 사람이 버전 1로 저장하려
하면 서버가 409를 반환합니다. 다른 사람의 수정이 조용히 덮어써지는 것을
막기 위한 것입니다. 사진 팝업을 닫고 다시 열면 최신 내용을 확인할 수 있습니다.

화면은 현재 보고 있는 컬렉션을 7초마다 확인합니다. WebSocket은 아니므로
다른 사람의 수정이 표시되기까지 약간의 시간이 걸릴 수 있습니다.

## 8. 이미지 검색은?

키가 없으면 함께 들어 있는 사진의 title/tags/author에서 검색합니다.
키를 설정하면 서버가 Pixabay에 요청합니다. API 키는 서버에만 둡니다.
24시간 캐시로 반복 요청을 줄이고 사진을 저장할 때 서버에 내려받습니다.
